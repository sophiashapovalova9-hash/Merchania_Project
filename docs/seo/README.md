# SEO-каркас Merchania

Скриншоты Lighthouse снимаются в браузере на собранном сайте, не на `npm run dev`. Их кладут сюда:

- `docs/seo/before.png` — замер до правок, категория SEO
- `docs/seo/after.png` — замер после правок, те же настройки

Как снять: инкогнито, F12, Lighthouse, Mode = Navigation, Device = Desktop, только категория SEO.

## Что уже сделано в коде

- В `frontend/index.html` стоят `lang="ru"`, charset, viewport, title, description, canonical и Open Graph.
- На каждой открытой странице один `h1`, уровни не перескакивают. Подписи в подвале и фильтрах, которые были заголовками только ради размера, стали обычным текстом.
- `frontend/public/robots.txt` закрывает вход, регистрацию, восстановление пароля, кабинет, панель художника, корзину, оформление и `/api/`.
- `frontend/public/sitemap.xml` перечисляет публичные страницы. Домена ещё нет, поэтому адреса начинаются с `https://example.com`.
- На закрытых страницах React ставит `<meta name="robots" content="noindex, nofollow">`.
- Ответы API получают заголовок `X-Robots-Tag: noindex, nofollow`. Прямой порт API отдаёт свой `robots.txt` с `Disallow: /`.
- В nginx включено gzip. Это простой шаг по скорости из этой лекции. Подробный разбор Performance будет на занятии 20.

## Что Lighthouse может ещё показать

- Сайт на React: текст страницы появляется после JavaScript. Уникальные title и description для каждой страницы по заданию будут на практическом занятии 17. Сейчас общие метатеги лежат в `index.html`, а `noindex` ставится на закрытых страницах.
- В карте сайта девять карточек товаров прописаны вручную. Когда товары начнут добавляться часто, карту лучше собирать на бэкенде из базы. Для текущего каталога ручного файла достаточно.
- `example.com` нужно заменить на настоящий домен в день публикации. Пока домена нет, так и просит задание.
- Тяжёлые фото каталога и метрики Core Web Vitals в эту сдачу не входят: это занятия 19 и 20.
